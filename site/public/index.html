Security by design

The secret isn't guarded by a prompt. It's out of reach.

Prompt instructions can be argued with. Snowflake roles can't. The floor is a governance boundary, not a sentence in a system prompt.

  1. STOREFRONT_ROLE can't read PRIVATEThe buyer session's role has no grants on the schema holding cost basis, policy and levers.
  2. Secure view masks cost and floorFor that role, cost and floor columns come back as NULL.
  3. Owner's-rights procedures do the mathThey compare the offer to the floor and return only ACCEPT / COUNTER / REJECT / FINAL plus a hint without numbers.
  4. The MCP server exposes only the agentNo raw SQL tool, which would bypass the agent.
  5. No role escalation via OAuthOAUTH_USE_SECONDARY_ROLES = NONE; ALLOWED_ROLES_LIST = ('STOREFRONT_ROLE').
  6. Everything is on the recordEvery move is written to NEGOTIATION_LEDGER.

Why Snowflake + Claude

Truth in the warehouse. Talk in the model.

Snowflake

Holds and enforces the truth

Costs, floors, policy, roles and the ledger all live where the seller's data already lives. Governance decides what the agent can see.

Claude

Does the reasoning and talking

Claude reads the buyer, trades concessions, writes the counters, and refuses social engineering. It works from decisions, not secrets.

Policy is data

Change rules with an UPDATE

Margins, buffers, round limits and approval thresholds are rows in a table. No prompt edits, no redeploy.

Live policy, demonstrated: diesel price changes in Snowflake reprice the floor and list instantly. Diesel $3.80 → $4.60 moves the levered floor:

$3,853.45 → $4,056.27
Onboarding

Get connected

Sellers set up a storefront in their own Snowflake account. Buyers connect their AI agent with a URL.

  1. Prerequisites

    A Snowflake account with ACCOUNTADMIN for setup. Claude models on Cortex need cross-region inference enabled:

    ALTER ACCOUNT SET CORTEX_ENABLED_CROSS_REGION = 'ANY_REGION';

    Check that Claude works:

    SELECT AI_COMPLETE('claude-sonnet-5', 'Reply with exactly one word: pong');

  2. Install

    Clone the repo, then run the SQL files in order in a Snowsight worksheet.

    git clone https://github.com/ardalangh/counteroffer.git
    00_setup→01_schema→02_seed→03_governance→04_procs→05_agent→06_mcp

    02_seed loads demo data; skip it or replace it if you're mapping your own tables. Future: a one-click Snowflake Native App.

  3. Map your data

    • Lanes / products
    • Carrier cost basis → PRIVATE.COST_BASIS
    • Customers and tiers

  4. Set your rules (no code)

    Pricing is two tables in the private schema. Changing policy is an UPDATE, not a redeploy.

    TableWhat it holds
    PRIVATE.PRICING_POLICYTarget margin, minimum margin, absolute minimum, counter buffer, max rounds, approval threshold, per customer tier
    PRIVATE.CONCESSION_LEVERSWhat each concession is worth (12-month term, ≥30 loads/week, 48-hour pickup, NET15, NET60)

  5. Publish your storefront

    Create the OAuth integration, then read the client credentials to give to buyers:

    CREATE SECURITY INTEGRATION STOREFRONT_MCP_OAUTH
  TYPE = OAUTH OAUTH_CLIENT = CUSTOM ENABLED = TRUE
  OAUTH_CLIENT_TYPE = 'PUBLIC'
  OAUTH_REDIRECT_URI = 'https://claude.ai/api/mcp/auth_callback'
  OAUTH_USE_SECONDARY_ROLES = NONE
  ALLOWED_ROLES_LIST = ('STOREFRONT_ROLE');
SELECT SYSTEM$SHOW_OAUTH_CLIENT_SECRETS('STOREFRONT_MCP_OAUTH');

    Create the MCP server with one tool, the agent:

    CREATE OR REPLACE MCP SERVER COUNTEROFFER.PUBLIC.STOREFRONT_MCP
  FROM SPECIFICATION $$
  tools:
    - title: "Acme Freight sales desk"
      name: "acme_freight_sales"
      type: "CORTEX_AGENT_RUN"
      identifier: "COUNTEROFFER.PUBLIC.ACME_SELLER"
      description: "Request freight quotes and negotiate truckload contracts."
  $$;

    Your storefront URL:

    https://<org>-<account>.snowflakecomputing.com/api/v2/databases/COUNTEROFFER/schemas/PUBLIC/mcp-servers/STOREFRONT_MCP
    Use hyphens, not underscores, in the host. Share this URL and the OAuth client ID with your buyers. Keep client secrets out of email threads and repos.

  6. Watch & approve

    Deploy the Seller Console (Streamlit in Snowflake) to watch live negotiations, see injection warnings, adjust diesel, and approve or reject orders above your threshold.

  1. Get the seller's storefront URL

    Ask the seller for their storefront URL and an OAuth client ID (and a client secret, if they issue one). It looks like:

    https://<org>-<account>.snowflakecomputing.com/api/v2/databases/COUNTEROFFER/schemas/PUBLIC/mcp-servers/STOREFRONT_MCP

  2. Add it as a connector in Claude

    Settings→Connectors→Add custom connector
    • Paste the storefront URL.
    • Authentication: Sign in now.
    • OAuth client: Use your own OAuth client. Enter the client ID (and secret if the seller gave you one).
    • Connect, sign in, approve.

  3. Give Claude a mandate

    Set the tool to Always allow. Create a Project with your buying mandate, then tell Claude what to buy. It negotiates and asks you before booking.

    # Example Project instructions (Northwind Goods, fictional)
You buy truckload freight for Northwind Goods.
Lane: <origin> → <destination>
Volume: <loads per week>
Max contract term: <months>
Ceiling price per load: <$ amount>
Payment terms: prefer <NET15 / NET30 / ...>
Negotiate with the Acme Freight sales desk. Trade concessions only
within this mandate. Ask me before booking anything.

  4. Use any MCP-capable agent

    Claude Code, Claude Desktop, claude.ai, or your own agent via the Cortex Agents Run API. Buyers pay nothing.

Production notes

The demo uses synthetic data and a single demo login. In production, each buyer company gets its own identity (for example, External OAuth with their IdP), so the seller knows who's negotiating and applies that customer's tier.
